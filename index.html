Build vs Buy / Governance

Not every problem gets the same answer. This is the judgment call behind each module above.

Automate with rules

A deterministic workflow — same input, same output, every time. No model involved.

Use an AI agent

Claude reasons over unstructured input within guardrails, and a human can always review.

Keep the human decision

Judgment, safety or compliance calls that shouldn't be automated at all.

Criterion Automate with rules Use an AI agent Keep the human decision
RiskLow — outcome is fully predictableMedium — must stay within guardrails and be reviewableHigh — safety, compliance or financial exposure
Data sensitivityLow to medium — structured, non-judgmental dataMedium — often unstructured, not highly regulatedHigh — sensitive, regulated or highly contextual
FrequencyHigh — worth building fixed logic for repetitive volumeMedium to high — variable inputs that don't fit a fixed ruleLow — rare enough that automation ROI is weak
ComplexityLow — clear if/then logicMedium to high — requires reasoning over unstructured inputHigh or ambiguous — no stable rule captures it
CostLow upfront, low to maintainMedium — API/infra cost plus guardrail design and monitoringHighest per case, but avoids the cost of an automation failure
Need for judgmentNone — a human already made the decision once; the rule repeats itSome — pattern recognition and synthesis, always reviewableHigh — a genuine judgment call, not pattern matching
